Artificial · whole-app audit and follow-through

One app, one source of truth, safer browser edges.

A completed, behavior-preserving quality refactor across orchestration, Svelte presentation, saves, local workflows, configuration, tests, and retired legacy paths.

Completed 12 August 2026 · The balance redesign, a TypeScript migration, and dependency churn were deliberately excluded.

Result at a glance

One supported application

The stale Bootstrap/Rollup entry, renderer, styles, and duplicate simulator are retired. Vite/Svelte is the only runtime surface.

UI is a real boundary

Components render store-owned snapshots and issue commands. The store reacts to domain events without polling or reaching through manager internals.

Saves fail safely

Browser APIs live in a small adapter; import validates before confirmation, keeps a one-level recovery point, and restores it only after revalidation.

Live data is authoritative

eraData is the sole era definition. The prior player-facing names, descriptions, and timespans were retained exactly while duplicate data disappeared.

Architecture after the refactor

index.html → src/main.js → App.svelte

The store is intentionally a thin presentation adapter—not a duplicate game engine. Provider-specific browser behavior stays at the edge; rules remain in the game layer.

Findings ranked by impact

P0 Resolved

Manager-backed Svelte panels could freeze after progression

Trade, wonder, and prestige values were derived through stable manager references, so nested mutations did not reliably invalidate Svelte computations. The store now emits fresh display snapshots from domain events. A regression test proves a civilization-gated route updates without a reload.

P1 Resolved

Presentation duplicated rules and depended on polling

Components computed affordability, costs, eligibility, and availability through core internals, then manually refreshed. The store now owns rendered action, worker, upgrade, prestige, route, wonder, and progression views. Synchronous passive events are coalesced to one snapshot while commands remain immediately current.

P1 Resolved

Save, offline, and startup failure paths could lose state or feedback

Export could serialize a stale persisted save; future schemas could be overwritten; malformed offline timestamps produced NaN; clipboard rejection was unhandled; unload listeners leaked; and startup failures left an indefinite spinner. The browser adapter, validation guard, named cleanup, recovery UI, and focused tests close those paths.

P1 Resolved

Import overwrote a run with no undo path

A valid import is now sanitized before a clear confirmation. The current in-memory run and offline timestamp become a one-level backup; restoring it also validates through GameState, reloads runtime timers, and consumes the backup. This adds recovery without introducing a save-history system.

P1 Resolved

Two obsolete app paths and a parallel simulator created drift

The deployed Vite entry never used the Bootstrap page, yet the 811-line renderer was still bundled. The old screen, Rollup setup, styles, stale plans, and simulator are removed. The simulator used incompatible prestige, population, and worker maths; the live configuration is now the only logical source of behavior.

P2 Resolved

Era metadata had two conflicting authors

config.eras duplicated a subset of config.eraData, and their prose and timespans disagreed. All consumers now read the complete canonical record. A test guards every ordered era and confirms the duplicate map stays absent.

P2 Resolved

Developer and deployment workflows had misleading paths

The VS Code task referenced a nonexistent command; a canonical pnpm check replaces it. Jenkins now deploys the exact commit it verified rather than whatever reaches origin/main later in the run.

P1 Resolved

A high transitive package alert remained after the refactor

postcss resolved nanoid@3.3.16, below the patched 3.3.17 release. A pnpm workspace override now pins the compatible fixed patch without upgrading the app's direct dependencies; the production audit returns zero findings.

Changes made and why

  • Kept orchestration small and authoritative: configured cooldown enforcement, missing state events, notification/log buffering until Svelte attaches, and no legacy renderer branch.
  • Made the Svelte store the only presentation contract: immutable-ish views in, named commands out, no UI-side manager traversal or ad hoc refresh calls.
  • Added BrowserSaveAdapter for storage, clipboard, and confirmation ownership. GameState keeps parsing, migration, and validation—the actual domain work.
  • Added explicit import confirmation and a visible “Restore pre-import save” action. Reset clears that backup; the next import replaces it.
  • Retired the unsupported Bootstrap/Rollup surface and the drifted balance simulator instead of maintaining parallel implementations. Removed only dependencies used exclusively by those paths.
  • Canonicalized era data with the live player-facing metadata preserved, then migrated every runtime consumer.
  • Removed confirmed-unused helpers, timers, adapters, store exports, CSS, and unreferenced historical plans. Improved accessible status/error feedback and reduced-motion behavior.
  • Resolved the remaining high transitive security alert with a compatible nanoid@3.3.17 workspace override, avoiding a broad dependency update.

Delivery and repository hygiene

  • The refactor and the rebased pinned-Node Docker refresh were reviewed, checked, and merged to the fork's main branch through PRs #35 and #34; no upstream remote was used.
  • Two clean obsolete worktrees, nine stale local branches, and one superseded remote Docker branch were removed only after confirming their merged PR history or obsolete legacy dependency.
  • The repository now has one local worktree on current main, no stale remote topic branches, and no stashes. Unreachable Git recovery objects were deliberately left for normal retention rather than destructively garbage-collected.

Worthwhile follow-ups deliberately left out of scope

  • Balance redesign and new simulation tooling. The old simulator was retired because it disagreed with production. Any future balancing tool should extract small, independently tested pure formulas from the live game rather than recreate the runtime.
  • TypeScript migration. The project has JavaScript source and no tsconfig; adding a type migration would be churn rather than a proportionate refactor.
  • Multi-version save history or cloud storage. One recovery point solves accidental import loss without creating retention, account, or sync policy.
  • Browser end-to-end coverage and a Jenkins parser test. The focused Node suite and production build are green; adding a browser harness or Jenkins test environment is valuable future infrastructure work, not required for these changes.
The refactor favors the smallest model that makes correct behavior unsurprising: one UI, one canonical game definition, a thin presentation boundary, pure-ish orchestration, and browser complexity isolated at the edge.
