Artificial · whole-app audit

Smaller seams, fresher UI, safer saves.

A behavior-preserving code-quality refactor across architecture, game orchestration, browser edges, Svelte UI, tests, and local developer workflows.

Completed 12 August 2026 · Scope deliberately excluded redesigns, dependency churn, migrations, and destructive product changes.

Result at a glance

UI boundary restored

Svelte components now render store-owned snapshots and issue store commands. They no longer reach into manager internals or poll the entire game once per second.

Concrete gameplay defects fixed

Feature panels refresh after progression, civilization-locked trade routes stay disabled, click cooldowns are enforced by orchestration, and returning-player notices reach Svelte.

Browser edges made safer

Save export uses live state, future schemas are rejected consistently, malformed offline timestamps cannot produce NaN, and unload listeners are cleaned up.

Legacy cost isolated

The retained Bootstrap renderer is loaded only by its legacy DOM surface. Svelte’s initial JavaScript fell from 236.82 kB to 223.39 kB (68.91 kB → 65.87 kB gzip).

Architecture after the refactor

index.html → src/main.js → App.svelte
                              ↓
                         gameStore
             snapshots + commands + domain-event subscription
                              ↓
                         GameManager
       orchestration, lifecycle, game rules, presentation handoff
                              ↓
          GameState + resource / worker / prestige / route / wonder systems
                              ↓
          browser boundaries: localStorage · clipboard · offline lifecycle

index.bootstrap.html → GameManager → lazy-loaded UIManager (legacy only)

The store is intentionally small: it is a presentation adapter, not a second rules engine. Provider-specific browser behavior remains at the browser-facing edge; game rules remain in orchestration and domain systems.

Findings ranked by impact

P0 Resolved

Feature panels could stay frozen after game state changed

Prestige, trade-route, and wonder panels derived values from a stable manager reference. Svelte did not re-run the nested derivations when manager internals changed, so availability could remain stuck until reload. The store now produces new display snapshots directly from domain events; a regression test proves a manager-backed route view updates after a civilization event.

P1 Resolved

UI leaked core internals and relied on manual refreshes/polling

Components recomputed costs, eligibility, and views through GameManager, GameState, and individual systems, then called refresh() selectively. This duplicated rules and obscured missing event contracts. The new store owns rendered action, worker, upgrade, prestige, route, wonder, and progression views, while components remain dumb.

P1 Resolved

Several browser-boundary defects could lose feedback or progress

Export encoded an old localStorage save instead of current memory; corrupt offline timestamps yielded NaN; future local schemas were accepted then could be overwritten; rejected clipboard writes were unhandled; and beforeunload listeners survived destruction. Each is now covered by focused tests.

P1 Resolved

Displayed trade and cooldown rules were not consistently authoritative

The trade panel enabled affordable routes even when their civilization requirement failed. It now renders the domain’s canUnlock/reason. Click cooldowns previously existed only in the component, so reloads or orchestration calls bypassed them; they now belong to GameManager.

P1 Resolved

Legacy DOM code shipped to the Svelte application

GameManager statically imported the 811-line Bootstrap UIManager, although Vite deploys only the Svelte entry. The legacy renderer remains supported but is now dynamically imported only when its legacy DOM exists.

P2 Resolved

Dead state and workflow friction added noise without value

Removed confirmed-unused worker timers, configuration blocks, store exports/mutators, and CSS. Replaced the broken VS Code npm run serve task with pnpm tasks and added one canonical pnpm check command used by Jenkins and documented in the README.

P2 Resolved

Small accessibility gaps were inexpensive to close

Notifications now use a polite live region, the log toggle exposes its expanded state and controlled panel, motion-sensitive toast/cooldown animation is reduced, and prestige headings no longer skip levels.

Open, intentionally

The balance simulator is a drifted exploratory model

scripts/balance-sim.js uses different prestige, population, and worker calculations from the live game. It still passes its strict scenarios, but that is scenario feedback—not proof of production equivalence. It was not rewritten into a second engine.

Changes made and why

  • Introduced one explicit game-store adapter: snapshots for rendering, commands for user actions, and event subscriptions for synchronization. This removed repeated component logic and the one-second Svelte polling loop.
  • Added missing domain notifications for era specialization, prestige restoration, perk purchases, and action cooldown transitions so the store can update at the source.
  • Buffered notifications and log entries until a presentation surface attaches, preserving the returning-player offline message in Svelte without changing offline production.
  • Moved configured click cooldown enforcement into orchestration, then exposed its display state through the store. The legacy DOM flow still works; Svelte no longer owns the rule.
  • Extracted the duplicate specialization-multiplier scan and the repeatedly allocated population-support mapping from GameManager.
  • Made save serialization reusable by local save and export, rejected newer schemas before state mutation, and handled browser failure paths cleanly.
  • Kept the legacy Bootstrap surface instead of deleting it. Dynamic loading prevents it from burdening the deployed Svelte entry while preserving current direct-use behavior.
  • Kept targeted existing tests, reduced duplicated test-environment setup, and added regressions only where a concrete defect was found.

Worthwhile follow-ups deliberately left out of scope

  • Decide whether to retire the legacy Bootstrap/Rollup app. It is stale relative to Svelte, but removal changes a potentially supported surface and needs explicit product approval.
  • Consolidate browser persistence behind a small save adapter. The safety fixes are in place, but moving all localStorage/clipboard/offline ownership at once would be a larger boundary change than necessary here.
  • Make one era-metadata source canonical. config.eras and config.eraData duplicate some user-facing copy; choosing a source requires editorial/product judgment.
  • Clarify or retire the balance simulator. If it should guide balancing, share individually tested pure formulas with production incrementally—do not create a generic second runtime.
  • Pin Jenkins deployment to the verified SHA. The current deploy stage independently fetches origin/main, so a later push could deploy a different commit. This is an infrastructure change and was left untouched.
  • Add product-approved import recovery and startup-error UX. Import currently overwrites the run after validation, and an initialization rejection can leave the loading screen visible. Both are user-facing behavior decisions.
  • Do not start a TypeScript migration by default. The app has no TypeScript source or tsconfig. Adding one would be churn, not a proportionate quality fix.
This audit favored the smallest model that makes the actual behavior obvious: dumb UI, explicit adapter boundary, pure-ish orchestration, and browser-specific complexity at the edge.
